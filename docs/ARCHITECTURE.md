# 系统架构与可核验范围

## 身份与消息

现有程序固定 X Layer 196、168 处理器、居民区域 2 及判官 `1.2.168`。居民钱包通过 TapeOut 电路容器发送 TapeSend。承诺、揭示、裁决、计分回执和参数消息由 `SCV1` ref 与关联 ID 连接；解析器校验消息载荷 digest、作者或判官身份、历史区块、时间及原承诺引用。

## 公开记录与服务数据库

链上保存身份/背书操作与消息。D1 保存索引、租约、任务、交易日志和历史缓存，使公开查询及自动执行更快。签名交易先保存再广播；重试重发相同字节，避免以另一个 nonce 再付一次费用。最终状态来自安全区块中有效消息的收录，单次广播或回执不等于全部核验完成。

事前计分回执只公开参数哈希。参数和 salt 在公开前保留在运营者数据库中，到期揭示后公开参数消息。已经公开的结果可以独立重建；尚未公开的私有参数不能从哈希恢复。运营者仍需维护备份、密钥、日志与可用性。

## 三种核验层次

| 方式 | 检查什么 | 依赖什么 |
| --- | --- | --- |
| 前端读取 API | 案件、来源、事前回执与分数状态 | 判官索引的真实性与及时性 |
| Agent `indexed-evidence-recomputed` | 公开参数/历史摘要、p、价格判定、整数分与排序 | API 提供链上权限、背书及消息真实性依据 |
| 本地独立重建 | 从公开链重新索引，核对历史身份/所有权/背书，独立取初始价与历史样本，重新结算 | RPC 一致性、历史数据可获得、代码/规则正确 |

独立重建结果对应具体 `asOf`，历史结果不能冒充当前榜单。它新建 SQLite，不访问线上 D1，也不加载签名私钥。已完成实例见 [公开凭证目录](../verification/README.md)。

## 自动运行

Worker 每分钟尝试索引、缓存准备、价格证据、计分准备与交易执行；交易签名受到持有人身份、协议固定值、nonce 和费用预算约束。任务失败后按状态重试。历史缓存准备与广播交易跟踪可以在安全区块读取短暂失败时继续处理，最终揭示/裁决仍需严格核验。

## 信任与限制

判官具备收信密钥和签名能力。程序约定到期公开，但不能证明判官在链下没有提前读取。底层协议存在升级边界，执行器固定所核对的实现与权限，变化时停止。现有应用没有独立安全审计。

Chainlink 与 OKX 是固定外部价格来源；“双源”不意味着来源完全没有相关性。多节点一致也不等于所有节点绝无串通。计分 p 是重叠历史窗口频率，并非真实概率认证；NAND 背书是成本与可追踪性约束，不是完整的反女巫方案。

## 新运营者

本仓库是现有 168 的实现，而不是仅换一个 Worker 名称就可运行的新判官模板。运行独立判官前须修改并测试处理器、居民区域、判官端点/容器、前端 API、发布目标和权限配置。只读消费者与本地测试无需这些权限。
