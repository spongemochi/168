## 计分规则

1. 背书电路无需开通容器；消息由居民身份容器发送。首笔案例的居民身份为 `2.2.168`，独立背书为 `3.2.168`，判官为 `1.2.168`。居民另创建一枚 NAND 背书电路；背书必须早于封存区块。核验流片 calldata、铸造日志、一枚 NAND 销毁、历史所有权及实际封存发送钱包。一枚背书只支持一条判断，判官排除。
2. 密文固定 `scoringVersion=168-score-history-v2`、`claim.ruleVersion=168-price-usd-v2` 和 `slot`。支持 BTC/USD、ETH/USD，严格 `>` / `<`；期限 1 小时至 7 天，界面建议两小时。
3. 初始价取封存前一分钟边界的历史价格。三源取中位数；双源须 OKX+一路 Chainlink、价差不超过低价 2%且对阈值判断一致，取均价。双源参数固定后，第三源恢复不会改写初始价或 p。
4. 封存前最近 4320 根完整 OKX 美元指数小时收盘价形成历史窗口。期限向上取整为 H 小时；遍历所有 H 小时窗口，以整数交叉乘法比较 `初始价×历史终价` 与 `目标价×历史起价`。
5. `p=(命中历史窗口数+1)/(有效窗口数+2)`，四舍五入至六位小数。有效窗口至少 1000，p 限于 `[0.05,0.95]`；超出范围不收录。p 是历史频率估计，重叠窗口不视为独立样本。
6. 参数绑定版本、链、处理器、承诺 ID、原条件、背书、提交时钱包、居民编号、初始价来源、历史摘要及随机 salt，用规范 JSON 计算 SHA-256。封存后 600 秒内、开舱前须有链上参数哈希回执；晚回执不计分，不补录。
7. 只有有效揭示后才发公开参数消息。重新核验原密文选择、背书、原始价格证据、历史摘要与 p，且裁决符合原固定规则，才能计分。
8. 命中 `+1−p`，未中 `−p`；百万分整数精度累计。每个 case 只计一次；重复索引、重复请求不增加分数。归属按提交时钱包+居民编号，转让不转移旧分数。

## 排行榜与资源分配

`GET /api/leaderboard` 提供规则版本、索引截止时间、每笔已核验记录、居民累计分数和样本数。

- 正式榜：至少十条有效结算，按分数降序，再按样本数、钱包和居民编号排序。
- 样本积累中：已有可核验分数，但尚未达到正式榜门槛。
- `allocationRanking`：仅正式上榜居民，包含名次、钱包、居民编号、分数、结算数量和原始案件 ID。可作为后续资源分配输入；本版本不擅自确定资源权重或发放资金。
- 页面支持榜单 JSON 导出、案件回执及公开参数链接、历史样本下载。读取失败显示无法读取和重试按钮，不能视为零分或空履历。

## 部署与运行

公开仓库包含当前 v6 源码和六份迁移。配置、部署顺序与权限见 [Worker README](../judge-worker/README.md)。历史 v4/v5 修复包属于本地归档，不用于覆盖当前服务。

网站发布需使用站点持有人钱包；Worker 部署不会替换链上文件。以下命令在仓库根目录运行，仅查询或重建，不发送交易：

```sh
node tools/check-scoring-status.mjs --case 0x1831cb8dc71ab9f8e5f4509aee6ace0e4f3f303b54951f2d0899d219c63fbd98
node tools/rebuild-scoring.mjs
```

需要代理时设置 `SCORE_DIAGNOSTIC_PROXY=http://127.0.0.1:15236`。后台 ready 只表示可以受理计分，并不表示某条案件已经完成；案件须有及时回执、公开参数、有效裁决和已核验结算记录。

历史缓存分批断点续读，齐备连续 4320 根样本后才允许付费背书；每小时补新数据并保留延迟核验窗口。缓存或报价不可用时不编造 p，旧普通判断不补分。

### 从失败的本地重建继续诊断

若链上消息已扫描完成，但分数因 RPC 一致性未通过，使用 `tools/rebuild-scoring.mjs --resume verification/scoring-rebuild-时间戳.sqlite --diagnose`。脚本要求同一重建的 JSON 结果与 SQLite 快照对应，复制到新本地数据库后继续，不覆盖旧结果、不访问线上 D1，也不重新扫描消息。诊断打印失败阶段、RPC 方法、节点 HTTP 状态及返回错误；仍要求原有独立节点一致性。历史背书核验先在原封存区块严格读取工厂目录中的 168 号处理器，确认其合约地址后再按原流程解析作者身份。这避免冷启动按容器反查时一次扫描 80 个无关处理器，仍使用相同历史区块、原独立节点一致性和所有权核验。任何未核验记录会保留在 `unverified`，脚本以非零状态结束。复用快照只证明该历史索引截止时间的重建，不声称是最新榜单。

## 验证与边界

本地测试覆盖真实 TapeSend 消息编码、密封选择→回执→揭示→价格裁决→参数公开→核验→计分、参数篡改、背书复用、历史缺口/冲突、重复重放、旧交易迁移、RPC outage 独立跟踪、前端读取失败与重试。模拟链数据的端到端测试不能代替新主网背书日志及 Cloudflare 运行验收。

安全区块读取暂不可用时，已广播交易仍可检查回执并标为“已打包、待安全索引”；它不会因此变成已核验揭示或已裁决。缓存继续准备，原严格身份与安全区块要求不降低。待节点恢复再索引。

实际历史 API 可用性、Worker CPU/子请求额度、事前十分钟回执窗口及浏览器钱包完整流程仍以用户终端/钱包反馈验收。按原预算可能暂停发信，不突破费用上限。

当前不对缺少公开凭证的未揭示案件扣分；守约评审、社区裁决和实际资源发放没有混入判断分。参数公开前如丢失 D1 内私有参数和 salt，不能从哈希恢复，不能补录；保持现有 D1，不删除交易日志。

需要关闭计分时，保留 v6 代码和数据库，将新包 `SCORING_ENABLED=false` 后重新部署。不能用旧 v5 覆盖已写入新计分类型的服务；旧包只作归档。关闭后未完成的计分工作会停止，已有已核验记录仍可读。
